# AGENTS.md

Open-source Chinese-language book "深入理解 AI Agent：设计原理与工程实践" (10 chapters) with 95 companion experiment projects. Not a typical app: most work is Markdown prose (`book/`) plus independent runnable Python experiments (`chapterN/<experiment>/`). Canonical text is Chinese in `book/`; `book-en/`, `book-ja/`, etc. are community translations that legitimately lag the original — do not "sync" them.

## Environment & setup

- Python 3.11–3.13 (project floor `>=3.11,<3.14`; CI also checks 3.11/3.13).
- Install per chapter, from the repo root:
  - `uv sync --locked --extra chN` (uses `uv.lock`)
  - pip fallback: `python -m pip install -e ".[chN]"`
- Merge extras in ONE command: `uv sync --locked --extra ch7 --extra unsloth`. Re-running sync alone re-syncs to current selection.
- `all` is a CPU-friendly aggregate; it deliberately EXCLUDES the GPU stacks `train`, `unsloth`, `vllm` (Linux/x86_64 only). macOS/CPU users install those opt-in extras or use per-experiment `requirements.txt` in a separate venv.
- Run experiments from the repo root: `uv run python chapter1/context/main.py`.
- Credentials: copy `.env.example` → `.env` at root for shared CLIs; some experiments read their own adjacent `.env`. NEVER commit real keys. Only use `--provider ollama` / start Ollama when the experiment README explicitly lists it.

## Tests & lint

- Experiment tests: `cd chapterN/<exp> && python -m pytest tests`. Root suite: `python -m pytest tests` (needs `pip install -e ".[dev]"`; imports `scripts.*` and `agentbook.*` directly).
- Tests must be offline/deterministic — no live APIs, network, GPU, or model downloads. Manual/live smoke scripts go under `tests/manual/` and must NOT be named `test_*.py` (pytest would collect them). Add `tests/conftest.py` path bootstrap when importing root-level modules; never change user-facing imports.
- Ruff: `line-length = 100`, `force-exclude = true`. Vendored third-party trees are excluded and carry their own requirements — do not reformat or refactor inside:
  - `chapter8/gaia-experience/AWorld`, `chapter8/browser-use-rpa/browser-use`, `chapter2/prompt-engineering/tau_bench`
- Exception: `chapter1/web-search-agent/tests/` is checked by black at 88 cols (`[tool.ruff.format] exclude`), so don't reflow it to 100.

## Shared plumbing (`agentbook/`)

- `agentbook.providers` is the single provider-resolution layer (`resolve_backend`) that chapters 1–3 CLIs depend on. Changing it can break many experiments at once; CI has dedicated workflows for this (`provider-adoption-tests.yml`, `web-search-agent-tests.yml`).
- Keep teaching logic inside the experiment directory; only shared plumbing belongs in `agentbook/`.
- Provider model IDs and key-env mapping live in `agentbook/providers/registry.py`; adding a provider should be a registry-only edit (tested invariant). Never commit API keys; tests set key env vars to `""` so resolver bugs fail rather than silently passing.

## Website (MkDocs)

- Docs deps: `pip install -r requirements-docs.txt` (mkdocs-material 9.x, pinned — do not bump to 2.x). CI sets `NO_MKDOCS_2_WARNING=1`.
- Build: `bash scripts/build_site.sh` then `mkdocs build -d site`. `scripts/build_site.sh` assembles a generated staging tree into `_web/` (gitignored) and **never modifies source files**.
- Do NOT edit anything under `_web/` (esp. `_web/extras/site-i18n.generated.js`); it is regenerated by the `site_i18n.py` MkDocs hook. The hook also validates the i18n catalog and refuses to build if it drifted.
- `book/chapterN.md` is promoted to `book/chapterN/index.md` inside the build (URL stays `/book/chapterN/`); translated editions stay flat files. Keep image/link references in the SOURCE files correct relative to the repo, not the build.
- Adding/removing a language or nav entry requires updating `mkdocs.yml` (`extra.languages`), `extras/site-nav-i18n.json`, and then running `python scripts/site_i18n.py` + `python scripts/check_i18n_consistency.py` (this is the `i18n consistency check` CI job).

## Book builds (PDF/EPUB)

- PDFs need pandoc + xelatex + ElegantBook + CJK fonts; each `book*/` dir has `build_pdf.sh`. EPub: `./build_epub.sh [lang]` (lang codes: zh-CN zh-TW en es id ar ru ta vi tr ja ko hu). `all` does not yet include ja/ar — build those explicitly. Generated PDFs/EPUBs are gitignored.
- Release flow: pushing `book*/` to main triggers `build-latest.yml` (macOS runner) which rebuilds PDFs+EPUBs and uploads to the rolling "latest" pre-release. Versioned releases are cut manually. On non-main refs, the build job only verifies and uploads as artifacts.

## External repo checkouts & evidence

- Chapters 6/7/9/10 map to ~22 external repos that must be cloned into specific chapter dirs at pinned SHAs (see README appendix + `docs/EXPERIMENT_STATUS.md`). Cloning/installing is NOT experiment completion.
- Experiment status/evidence gates are tracked in `docs/EXPERIMENT_STATUS.md` and per-chapter `EXPERIMENT_LEDGER.md`. "Complete" requires retained evidence committed to the repo, not a local run. API keys must be scanned out of any retained receipts.

## Conventions

- Experiment layout + install/test conventions are codified in `docs/EXPERIMENT_CONVENTIONS.md` — read it before adding/restructuring an experiment.
- Baseline validation for a layout-only change: `git diff --check`, `python scripts/check_i18n_consistency.py`, `uv lock --check` (CI's `dependency-resolution.yml` runs `uv lock --check` + dry-run sync for every extra on 3.11 and 3.13).
- CI runs on Linux/macOS via bash; build/CI scripts assume bash, not Windows PowerShell.
- `.coderabbit.yaml` configures CodeRabbit review in Chinese.
