from types import SimpleNamespace
from unittest.mock import MagicMock
from agent import ContextAwareAgent, ContextMode

def _choice(*, content=None, tool_calls=None, reasoning=None):
    msg = SimpleNamespace(
        content=content, tool_calls=tool_calls, reasoning_content=reasoning,
        model_dump=lambda: {
            "role": "assistant", "content": content,
            "reasoning_content": reasoning,
            "tool_calls": [
                {"id": tc.id, "type": "function",
                 "function": {"name": tc.function.name,
                              "arguments": tc.function.arguments}}
                for tc in (tool_calls or [])
            ],
        },
    )
    return SimpleNamespace(message=msg)

def _response(choice, resp_id):
    # 顶层的 model_dump 让 api_turns 里带上 response.id —— 契约要靠它
    return SimpleNamespace(
        id=resp_id, choices=[choice],
        model_dump=lambda: {"id": resp_id,
                            "choices": [choice.message.model_dump()]},
    )

call = SimpleNamespace(id="call-1",
    function=SimpleNamespace(name="calculate",
                             arguments='{"expression": "2 + 2"}'))
turn1 = _response(_choice(tool_calls=[call], reasoning="I should add."), "resp-1")
turn2 = _response(_choice(content="FINAL ANSWER: 4", reasoning="Done."), "resp-2")

agent = ContextAwareAgent("test-key", ContextMode.FULL, verbose=False)
agent.client = MagicMock()
agent.client.chat.completions.create = MagicMock(side_effect=[turn1, turn2])

result = agent.execute_task("compute 2+2", max_iterations=5)

print(result["completed"], result["final_answer"])
print(agent.client.chat.completions.create.call_count)
for t in agent.trajectory.api_turns:
    print(t["iteration"], [m["role"] for m in t["request"]["messages"]])
验证标准
  • 输出 True 4、调用次数 2
  • 两轮的 role 序列分别是 ['system','user'] 和 ['system','user','assistant','tool']
  • 把第 2 轮 content 改空后:completed 变 False——空终止响应不算完成

假响应为什么非要带 id?因为契约的 has_provider_response_ids 只认真实 provider 响应 ID。没有它,即使请求形状全对,契约也判失败。这不是多余的形式主义——它是 mock 与真实证据的分界线,direct_real_api_evidence 就靠这一条。

这一题的核心发现

在你那次失败运行里,without_reasoning_degraded 居然是 True。为什么?

因为 no_reasoning 臂被 429 打挂了,final_answer 是 None,于是「答案不正确」→ 被算成「思考被移除后性能退化」。一个根本没跑起来的臂,伪装成了「正文断言被复现」。

同理 without_tool_results_repeated_action 和 without_history_repeated_action 变成 False——不是没重复,而是压根没跑。

这就是为什么 analyze() 必须先过 contracts + direct_real_api 两道门,才允许谈 behavior claims:失败运行会生产看起来很正常的行为指标。也解释了为什么 experiment_execution_accepted 要求「five arms ∧ contracts ∧ direct api ∧ baseline correct」四项同时成立。

import json
from pathlib import Path

EXPECTED = ("9602895.73", "2400723.93")
MODES = {"full","no_history","no_reasoning","no_tool_calls","no_tool_results"}

def correct(answer):
    norm = (answer or "").replace(",", "").replace("$", "").replace(" ", "")
    return bool(answer) and all(n in norm for n in EXPECTED)

def verdict(ev):
    arms = ev["arms"]
    by_mode = {a["mode"]: a for a in arms}
    exact_five = set(by_mode) == MODES
    contracts = exact_five and all(a["context_contract"]["passed"] for a in arms)
    direct = all(
        not a["using_openrouter"] and a["api_turns"]
        and all(t.get("response", {}).get("id") for t in a["api_turns"])
        for a in arms
    )
    behavior = {
        "full_baseline_correct":
            correct(by_mode.get("full", {}).get("final_answer")),
        "without_tool_definitions_no_tool_action":
            by_mode.get("no_tool_calls", {}).get("behavior", {})
                .get("tool_action_count") == 0,
        "without_tool_results_repeated_action":
            by_mode.get("no_tool_results", {}).get("behavior", {})
                .get("has_repeated_tool_action", False),
        "without_history_repeated_action":
            by_mode.get("no_history", {}).get("behavior", {})
                .get("has_repeated_tool_action", False),
        "without_reasoning_degraded":
            not by_mode.get("no_reasoning", {}).get("behavior", {})
                .get("canonical_answer_correct", False),
    }
    return exact_five, contracts, direct, behavior

ev = json.loads(Path("validation/real_20260729T153329Z/evidence.json")
                .read_text(encoding="utf-8"))
mine = verdict(ev)
stored = ev["analysis"]

八个「为什么」

这些是读这个实验时最容易滑过去、但一旦想通就再也不会忘的点。先自己想,再展开。

为什么 no_history 不用「滑一步窗口」这颗更温和的子弹?

因为滑窗仍然是历史。只要模型还能看到上一轮的工具结果,它就不会「每轮重新开始」,而正文描述的消融恰恰是「模型丢失全部跨轮记忆」。用滑窗会让实验看起来更漂亮(不那么容易崩),但它测的已经不是正文说的那个东西了。_prepare_messages_for_api 的文档串把这条写死在代码里。

为什么 no_tool_results 不删掉整条 tool 消息?

因为 assistant 消息里已经声明了 tool_calls,后面的 tool 消息是配套的回复。删掉它,消息序列就不自洽了——那是协议错误,不是信息缺失。实验要测的是「看不到结果会怎样」,不是「发一个非法请求会怎样」。所以保留消息骨架、只替换 content。

为什么契约检查的是「actual request」而不是 CLI 模式?

因为模式只是个字符串,它不保证代码真的照做了。你完全可以传 --context-mode no_history 而代码根本没实现消融——那样跑出来的数据会被贴上「no_history」的标签,却是假的。evaluate_context_contract 的文档串第一句就是:验证实际发出去的请求。这也解释了你那次失败运行为什么 contracts=False:四个臂压根没发出去请求。

为什么 hit_iteration_ceiling 在 main() 里被重算一遍?

summarize_arm 是个纯函数,也被单元测试直接调用,所以它只能用一个默认上限(代码里写的是 >= 5)。但真实运行时 --max-iterations 可能是别的值。run_experiment_1_1.py:414-416 就用实际配置的上限把它重算。这是「纯函数保持可测 / 运行器注入真实配置」的典型分工。

为什么 credential_value_recorded 永远是 False?

因为它不是「有没有记」的状态位,而是一条声明:这份证据里不含凭据值。真正记录的是 credential_source_env(用的是哪个环境变量名)。这样任何人拿到 evidence.json 都能复现「该设哪个变量」,但拿不到 key 本身。凭据永不入仓是这个仓库的硬纪律。

为什么 latest.json 是 copyfile,而不是软链接或一个「指向某目录」的小 JSON?

因为证据必须自包含、可单独评审。一个指针对象要求评审者再去跳转;一份完整拷贝则可以单独打开、单独算 SHA-256、单独归档。代价是磁盘上多一份副本——在证据完整性面前,这个代价很小。

为什么 task_success 在 agent 层是 None,而不是 False?

因为通用 agent 无法判断任意自然语言任务的对错。把「不知道」写成 False 等于凭空制造失败。所以 agent 层留 None,只有实验层(拿着 EXPECTED_NUMBERS 这种规范判据)才敢下结论。「未评估」和「评估为失败」必须是两个状态。

为什么假响应必须带 response.id?

因为 has_provider_response_ids 是每个模式都要求的必查项,而 direct_real_api_evidence 要求每一轮都有真 ID。这是 mock 与真实证据之间唯一无法伪造的界线:你可以伪造消息形状,但伪造不出 provider 的响应 ID。所以离线练习能做到「契约形状全对」,却永远得不到 direct_real_api_evidence=True——这是刻意的。
